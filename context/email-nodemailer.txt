  Recommendation: Gmail SMTP with App Password

  For a clinic starting with email notifications, this is the simplest and most practical approach.

  Why This Over Other Options

  | Approach                  | Verdict                                                               |
  |---------------------------|-----------------------------------------------------------------------|
  | Gmail SMTP + App Password | Γ£à Recommended ΓÇö Simple setup, uses existing Gmail, no extra services |
  | Gmail API (OAuth)         | Γ¥î Overkill ΓÇö Complex token management for a straightforward use case |
  | n8n + Gmail               | Γ¥î Overkill ΓÇö Adds infrastructure for something achievable in-app     |
  | Resend/SendGrid           | ≡ƒöä Future option ΓÇö Better if clinic gets a custom domain later        |

  How It Works

  1. Clinic enables 2-Factor Authentication on their Gmail account
  2. Generates an App Password (16-character password for apps)
  3. We store this securely in the database (encrypted) or environment variables
  4. Use Nodemailer in Next.js Server Actions/API routes to send emails

  Technical Details

  Sender: clinica@gmail.com (their actual Gmail)
  Method: SMTP via smtp.gmail.com:587
  Auth: App Password (not regular password)
  Library: Nodemailer (well-maintained, works with Vercel)
  Limits: 500 emails/day (personal) or 2,000/day (Google Workspace)

  Considerations

  | Aspect         | Detail                                                                   |
  |----------------|--------------------------------------------------------------------------|
  | Daily limit    | 500/day for personal Gmail ΓÇö Is this sufficient for the clinic's volume? |
  | Deliverability | Good for transactional emails, but Gmail may throttle if volume spikes   |
  | Cost           | Free                                                                     |
  | Setup time     | ~30 minutes                                                              |

  1.1 Create email_reminder_settings table

  CREATE TABLE email_reminder_settings (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    enabled boolean DEFAULT false,
    smtp_email text NOT NULL,
    smtp_password text NOT NULL,  -- Store encrypted
    appointment_scheduled boolean DEFAULT true,
    appointment_rescheduled boolean DEFAULT true,
    appointment_cancelled boolean DEFAULT true,
    reminder_24h boolean DEFAULT true,
    clinic_name text NOT NULL,
    clinic_address text,
    clinic_phone text,
    created_at timestamptz DEFAULT now(),
    updated_at timestamptz DEFAULT now()
  );

  -- Singleton pattern: only one row allowed
  CREATE UNIQUE INDEX single_email_settings ON email_reminder_settings ((true));

  -- RLS: Only admins can read/write
  ALTER TABLE email_reminder_settings ENABLE ROW LEVEL SECURITY;

  1.2 Create email_logs table (for tracking)

  Stores a record of all sent emails for debugging/auditing.

  CREATE TABLE email_logs (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    consulta_id uuid REFERENCES consultas(id) ON DELETE SET NULL,
    paciente_id uuid REFERENCES pacientes(id) ON DELETE SET NULL,
    email_type text NOT NULL,  -- 'scheduled', 'rescheduled', 'cancelled', 'reminder_24h'
    recipient_email text NOT NULL,
    status text NOT NULL,  -- 'sent', 'failed', 'skipped'
    error_message text,
    sent_at timestamptz DEFAULT now()
  );

  -- Index for querying by consulta
  CREATE INDEX idx_email_logs_consulta ON email_logs(consulta_id);
