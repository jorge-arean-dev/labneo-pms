# PMS Database Operations: Practical Guide

## 3 Skills, 3 Scenarios

### 1. New client? `/replicate-pms`

**Scenario:** "I signed a new client and need a full PMS for them."

```
MCP: doesn't matter (skill creates a new project)
Run:  /replicate-pms
```

Creates everything from scratch: Supabase project, DB schema, GitHub repo, Vercel deployment, admin user. Uses the SQL migration files in `deployment/migrations/`.

---

### 2. Changed the REF DB? `/create-ref-db-snapshot`

**Scenario:** "I just added a column / changed a policy / updated a function on the reference DB."

```
MCP: connect to REF DB (pms-database)
Run:  /create-ref-db-snapshot
```

Captures the current state of the reference DB into `deployment/ref-snapshot.json`. This is the snapshot that `/sync-db` compares against. Claude already updates the SQL migration files during the change itself; this skill captures the snapshot separately.

---

### 3. Client DB is out of date? `/sync-db`

**Scenario:** "I made changes to the reference DB and need to propagate them to silva-ricigliano (or any other client)."

```
MCP: connect to the CLIENT DB you want to sync
Run:  /sync-db
```

Reads the local `ref-snapshot.json`, queries the client DB, shows all differences, generates fix SQL, and applies it with your approval.

---

## Typical Workflow After a DB Change

```
1. Make the change (develop feature on REF DB as usual)
   Claude auto-updates deployment/migrations/ files

2. /create-ref-db-snapshot          (MCP → REF DB)
   Refreshes ref-snapshot.json

3. /sync-db                          (MCP → client DB)
   Propagates changes to each client
   Repeat for each client DB
```

---

## MCP Connection Cheat Sheet

| Skill | Connect MCP to |
|-------|---------------|
| `/replicate-pms` | N/A (creates new project) |
| `/create-ref-db-snapshot` | REF DB (`pms-database`) |
| `/sync-db` | Client DB (e.g. `silva-ricigliano-pms`) |

MCP can only connect to one project at a time. REF and client DBs may be in different Supabase orgs -- that's fine, the local `ref-snapshot.json` acts as the bridge.
